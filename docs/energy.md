# Энергия по счётчику ёмкости и напряжению банки

Основной показатель HTML и отдельный график Wh рассчитываются по двум величинам: **счётчику mAh** и **напряжению батареи**. График Ah имеет свою карточку и шкалу. Прежняя линия энергии по U×I×dt в HTML удалена.

## Какие поля используются

Позиции в таблице считаются с единицы, включая `$1` как первое поле. Индексы Python считаются с нуля после удаления `$`.

| Позиция / индекс | Величина | RAW первой строки Discharge_32 | Преобразование |
|---|---|---:|---|
| 9 / 8 | Знаковый счётчик заряда q | 0 | mAh; разряд в этом логе отрицательный |
| 12 / 11 | Напряжение первой банки | 4246 | / 1000 = 4.246 V |
| 3 / 2 | Время для оси графика и проверки разрывов | 0 | ms / 1000 = s |

При нескольких последовательных банках используется сумма ненулевых измерений полей 12–21. Эти каналы должны охватывать все последовательные банки; число параллельных элементов формат не определяет.

## Формула

Для пары соседних записей:

```text
Δq = q[i] - q[i-1]                            [mAh]
Uср = (U[i-1] + U[i]) / 2                     [V]
ΔE_разряд = Uср × max(-Δq, 0) / 1000          [Wh]
ΔE_заряд  = Uср × max( Δq, 0) / 1000          [Wh]
E_разряд = Σ ΔE_разряд
E_заряд  = Σ ΔE_заряд
```

Во время однонаправленного разряда это `E = Σ Uср × |Δq| / 1000`. Если напряжение ещё в сырых mV, общий делитель равен **1 000 000**. Дополнительное умножение на время или деление на 3600 не требуется: mAh уже является единицей заряда.

Используются приращения счётчика. Например, запись могла начаться при -500 mAh: неизвестная предшествующая энергия не добавляется. Произведение текущего напряжения на весь накопленный заряд не учитывает изменение напряжения на протяжении разряда.

В первой строке q=0, поэтому начальная накопленная энергия равна 0 Wh. Временная метка служит для оси X и проверки целостности записи. Изменение знака приращения относится к заряду либо разряду; противоположные направления внутри одного интервала из одного приращения восстановить нельзя.

## Пример из Discharge_32_CH1

| Время, s | q, mAh (поле 9) | U, mV (поле 12) |
|---:|---:|---:|
| 99 | -269 | 4108 |
| 100 | -272 | 4107 |

```text
ΔQ = |-272 - (-269)| / 1000 = 0.003 Ah
Uср = (4.108 + 4.107) / 2 = 4.1075 V
ΔE = 4.1075 × 0.003 = 0.0123225 Wh
```

Суммирование всех принятых интервалов даёт:

| Показатель | Результат |
|---|---:|
| Пакеты телеметрии / статуса | 11 329 / 95 |
| Длительность | 11 328 s = 03:08:48 |
| Период | 1 s |
| Счётчик: начало → конец | 0 → -36 324 mAh |
| Изменение счётчика | 36.324 Ah |
| Напряжение банки: начало → конец | 4.246 → 2.700 V |
| Отданная энергия по U·dQ | **125.278314 Wh** |
| Принятая энергия | 0 Wh |
| Повреждённые пакеты / пропуски расчёта | 0 / 0 |

Это энергия за записанный участок испытания. Для оценки полной доступной энергии нужен полный разряд с известными начальным зарядом, током и порогом завершения.

## Источник напряжения

`--energy-voltage auto` (по умолчанию) использует полную сумму обнаруженных последовательных балансирных каналов, когда они присутствуют в каждом отсчёте без пропусков между номерами. Если таких данных нет, весь расчёт использует силовой выход (поле 8, индекс 7). Источник явно указан в HTML, CSV и JSON.

`--energy-voltage cells` требует полных данных по банкам. `--energy-voltage output` принудительно выбирает силовой выход. Разница между этими точками измерения может включать падение на проводах/контактах и погрешности измерения.

## Качество данных

- XOR считается по ASCII от `$` до последнего `;` включительно. Повреждённые пакеты исключаются и перечисляются в отчёте.
- Большие разрывы (больше `max(2.5 × медиана Δt, медиана Δt + 2 s)`) не заполняются расчётной энергией: напряжение внутри разрыва неизвестно.
- Изменение счётчика при повторном timestamp не добавляет энергию; такой интервал помечается пропущенным.
- Подозрительное изменение знака приращения против устойчивого направления тока помечается как возможный сброс/скачок.
- Дополнительная эвристика скачка: `|Δq| > 5 × max(|Iпред|, |Iтек|) × Δt / 3.6 + 2 mAh`, при ненулевом измеренном токе. Допуск учитывает округление и переходные процессы. Это диагностика, а не доказательство аппаратного сброса.
- Ток используется только для проверки скачков счётчика; в численную формулу U·dQ он не входит. Число пропущенных приращений и подозрительных скачков показано в отчёте.
- Каналы CH1/CH2 должны находиться в разных файлах; несколько каналов не объединяются как одна батарея.

## Поля CSV и JSON

| Поле | Смысл |
|---|---|
| `counter_delta_mah_signed` | Приращение счётчика mAh |
| `battery_voltage_v`, `battery_voltage_source` | Напряжение для формулы и его источник |
| `counter_incremental_energy_wh_signed` | Знаковая энергия текущего принятого интервала U·Δq |
| `counter_discharge_energy_wh` | Накопленная отданная энергия; основной график при разряде |
| `counter_charge_energy_wh` | Накопленная принятая энергия |
| `counter_energy_throughput_wh` | Сумма энергии обоих направлений |
| `counter_energy_wh_signed` | Заряд минус разряд |
| `counter_energy_skipped`, `counter_jump` | Диагностика интервала |

В JSON и `summary.csv` поле `counter_energy_wh` содержит итог `counter_energy_throughput_wh`; `counter_energy_skipped_intervals` и `counter_jump_count` — количества диагностических событий.

Старые поля `energy_throughput_wh`, `integrated_energy_wh_signed`, `discharge_energy_wh`, `charge_energy_wh`, `battery_energy_wh`, `output_*` и `energy_difference_wh` сохранены для совместимости выгрузок. Они относятся к прежнему интегралу U×I по времени, их линии и карточки из HTML удалены. В этом логе прежний интеграл по банке равен 125.20946015 Wh. Разница с текущими 125.278314 Wh объясняется разными источниками заряда и дискретизацией; основной показатель теперь использует счётчик устройства.
